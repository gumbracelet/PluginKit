# Changelog

All notable changes to PluginKit are documented in this file.

The format follows [Conventional Commits](https://www.conventionalcommits.org),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Releases are tagged `vMAJOR.MINOR.PATCH`; the headings below carry the bare
version. See [docs/distribution.md](docs/distribution.md) for what each bump
promises.

Entries below this line are generated by the release workflow. To preview what the
next release will say, run `Scripts/pluginkit-changelog notes <version>`.

## [1.0.0](https://github.com/gumbracelet/PluginKit/releases/tag/v1.0.0) (2026-08-15)

### ✨ Features

* **core:** manifest, extension points with typed locality, capabilities, and the
  host service seams shared by both sides of the boundary
* **host:** `PluginManager` with manifest-first discovery, lazy activation,
  dependency and contract-version resolution, and per-plugin diagnostics
* **host:** capability brokering with scope attenuation, layered policy
  (managed → per-plugin → per-capability → per-sensitivity → default) and consent
* **host:** trust evaluation from code signature, team ID, quarantine, and
  duplicate contract-framework linkage
* **host:** layered configuration, scoped storage, and a topic-gated event bus
* **sdk:** `PluginPrincipal` bundle entry point, `PluginManifestBuilder`, and
  context conveniences for graceful degradation
* **inprocess:** `InProcessPluginRuntime` for registered and bundle-loaded plugins
* **testing:** `PluginHarness` with a serializing transport, `HostHarness`, and
  `PluginConformance`
* **cli:** `pluginkit describe`, `validate`, and `init`

### ✅ Tests

* 115 tests across 14 suites, covering the laziness, manifest-authority, trust,
  and attenuation guarantees
